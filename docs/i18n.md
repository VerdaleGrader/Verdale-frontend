# Languages (English and Thai)

The interface is available in English (the source language and the fallback) and Thai, with [next-intl](https://next-intl.dev). The address never carries the language.

| What            | Where                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------- |
| Texts           | `messages/en.json`, `messages/th.json` (same keys; `i18n/config.test.ts` fails if they differ) |
| Which language  | `i18n/request.ts`: the `vd_locale` cookie, then the browser's `Accept-Language`, then English  |
| Switch          | `components/layout/language-switcher.tsx` (sets the cookie, refreshes the page)                |
| Legal documents | `content/legal/{th,en}/`, see `docs/legal.md`                                                  |
| Tests           | `vitest.setup.ts` answers from the real messages in English; set `testLocale.current = 'th'`   |

## Translating a component

1. Add the text to `messages/en.json` under the area's namespace, then the Thai to `messages/th.json`.
2. `useTranslations('Namespace')` in a component (client or server, no `async` needed); `getTranslations` in `generateMetadata`. Keys are type-checked against `en.json`.
3. Names of the product's own concepts stay in English in Thai text: Space, Track, Collection. So do verdict codes (AC, WA, ...).

## Not translated yet

The landing page, header, footer, sign-in, accept-terms, legal pages, 404 and error pages are translated. The rest (Spaces, problems, submissions, settings, shared components such as empty and error states, and messages that come from Core) is still English.
